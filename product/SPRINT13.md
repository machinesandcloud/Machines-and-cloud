## Working local behavior

- `/api/platform-sms` is separate from legacy shop/bridge routing. It checks the canonical URL, signature, account, number, service and actual inbound Message receipt. It gives fixed public product/setup/sign-in guidance, records operator-only inquiries and never supplies private account data, promises a support ticket, or invokes a model.
- The default-off `MC_PLATFORM_SMS_ENABLED` gates ordinary replies. Verified STOP/START directives remain durable; provider acknowledgments are not duplicated. Repeated STOP and HELP while suppressed stay silent. Restart removes suppression without enrolling anyone in recurring texts.
- Immutable primary receipts prevent duplicate replies after concurrent delivery, a lost response or recent-history rollover. The latest500 projections roll forward automatically; older receipts remain private. A Houston-day cap permits at most500 application-prepared replies and resets automatically. It is not a dollar ceiling or a cap on Twilio's own keyword responses. Unconfirmed TwiML replies remain explicitly unconfirmed rather than marked delivered.
- The admin Inquiries screen shows the recent company SMS history separately from website inquiries and marketing eligibility. Only current verified operators may read it; sign-out clears it. There is no admin send action or marketing export of SMS contacts.
- Main health includes the platform's processing/budget status. A portable build gate exercises backend checks; the explicit local `--browser` pass separately exercises mobile/desktop rendering.
- Shop appointment permission now has version `ongoing_appointments_v2`. The real question explicitly includes future appointments, confirmations, reminders and cancellations. Only the exact delivered server question plus a later signed YES/SÍ can establish this scope. Earlier one-visit/unversioned permission never silently becomes ongoing authority. A second actual tool booking, STOP, restart and suppressed HELP are covered by regression checks.
