## Where MCP helps

- **Concrete candidate: Yelp Leads through Zapier MCP.** Zapier lists Create Message, Get Lead Details, Get Business Details and read/replied actions. It says one MCP call consumes two Zapier tasks. This adds app authorization, commercial terms and task costs; it is not M&C's own free Yelp access. Inbound discovery still needs the documented trigger/webhook workflow. [Yelp Leads MCP](https://zapier.com/mcp/yelp-leads), [Zapier authorization/setup](https://docs.zapier.com/mcp/quickstart).
- **Google's own Ads MCP is a read adapter.** Its published tools are search, resource metadata and accessible customers; it does not expose the LSA append operation. It can help verified discovery/reporting, not replace native replies or advertiser authorization. [Official server](https://github.com/googleads/google-ads-mcp/blob/main/README.md).
- An official provider-owned messaging MCP was not verified for Thumbtack, Angi, Houzz, Porch, Nextdoor, Bing Places or Meta in this review. Do not label every third-party directory entry an approved provider integration. Any MCP must call the same tenant-bound authorized action and retained outbox, enforce reply windows, record provider identity and retain unknown-send uncertainty. A generic agent with arbitrary send tools must not become a parallel dispatch queue.
- **Fresh Google setup correction:** the explicit sunset guide says developer tokens ended September 9, 2026; access now belongs to the OAuth credential's Cloud project, and old token headers are optional/ignored. Some overview/header pages still contain older text. Use current project access/SDK guidance rather than asking every owner for a developer token. [Migration and current onboarding](https://developers.google.com/google-ads/api/docs/api-policy/developer-token), [access levels](https://developers.google.com/google-ads/api/docs/api-policy/access-levels).
