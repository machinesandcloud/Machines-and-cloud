# V8 owner mail in the existing Calendar actor

The optional owner-mail route uses the Calendar actor's serialized command stream and the same supplemental control JSON-lines journal. It imports the accepted factory as `scripts/calendar-native-mail.mjs`; it never imports a closed controller. No application, provider or borrowed-Swift implementation changed.

The existing control caps remain48 physical HTTP/Git starts,16 mutations and2 builds. Mail has separate immutable40 native invocations/3 message reads, one invocation reserved for conditional Inbox restore. Native rows and their monotonic revision live in that same journal. A conditional save reserves each invocation before execution; the existing Python flock remains held across the native child. A second process cannot dispatch that row or race its cleanup. Unknown rows cannot be rearmed, counters cannot reset, and a lost acknowledgement never causes an automatic repeat.

Create the finalized Calendar packet first. After its SHA is fixed, Root may create owner0600 `/tmp/mc-calendar-v8-private-20261025/mail-execution-binding.json` in its owner0700 directory. Its exact fields are `version:1`, `state:'READY'`, `phaseId`, `packetSHA256`, `candidateCommit`, `approvedAt`, `approvalExpiresAt`, `factorySHA256`, and `configSHA256`. Packet/phase/candidate/clock values must match the approved packet. `factorySHA256` pins the tracked factory bytes; `configSHA256` pins `/tmp/mc-calendar-v8-mail-prep-20261025/mail-sources.json`, which in turn pins the six owner-only JS sources, Swift source/binary and navigation config. The binding/config digest cannot be embedded back into the packet whose digest they contain. No approval is generated by this adapter.

Start the existing actor with the additional pair `--mail-binding-sha256 <raw binding SHA256>` after its normal `--execute <private packet> <packet SHA256>` arguments. Binding, clock, config and factory are checked before control initialization. Without the optional pair the old actor path remains available and the new `nativeMail` command rejects. No closed ledger can be reopened.

Mail commands retain the factory's exact shape: `{action:'nativeMail',mode:'url',url:<approved search or conditional original Inbox>}` or `{action:'nativeMail',mode:'read'|'private',source:<exact approved source>}`. Only `owner-extract.js` is a message source and it requires private mode. Its public reply is only `privateMailDataSaved:true`; extracted links stay in the existing private mail-link file. The actor checks current Calendar authority before work and again after reservation/source awaits: closed or expired phases and an active borrowed Google handoff cannot run mail; halted/cleanup state permits only exact conditional Inbox restore. Private/source/clock checks repeat under the journal lock immediately before native dispatch.

Root still observes/selects the exact fresh message and converts its private link to the existing actor's exclusive email input using the existing `exactCalendarMessage` contract. A copied prior token or stale header time is not fresh evidence; no token/link is printed. Exchange both controlled owner messages before final mail Inbox restore, because `restoreAttempted` is terminal. Restore dispatch is not proof of arrival. The ordinary borrowed-tab/readback procedure separately observes the Inbox before Google handoff.
