# Operator service checks

The admin customer detail now includes **Check authorized services**. An operator supplies a reason; the server checks the operator session, current allowlist membership, customer identity and management revision. The primary client CAS saves the request, actor, reason and audit entry before any worker dispatch.

The action rechecks already-authorized phone, texting, calendar and message work. It does not collect customer attestations, grant purchase authority, reset uncertain sends, change provider IDs, or mark delivery successful. Closed customers can request checks so retained cleanup can continue. The dialog explains that fixed platform workers may also process other customers' already-authorized work.

`lib/service-reconciliation.mjs` projects the audited request into a durable job and fair queue. If either projection is lost, a bounded scheduled client scan repairs it from the source receipt. A current pending request prevents another duplicate operator request. Dispatch uses only the existing fixed background functions; callers cannot supply URLs, provider adapters, resource IDs or a new consent record.

States distinguish `queued`, `running`, `waiting_platform`, `retry`, `checks_dispatched`, `needs_attention` and `superseded`. Gates closed leaves the request saved with no network work and no consumed retry budget. Actual dispatch failures stop after three attempts. A dispatch receipt confirms only that checks were requested; the service and delivery receipts show their actual results separately.

Persistent dispatch exceptions remain in health after leaving the active queue. A later successful request for the same tenant resolves the dispatch exception while preserving the older receipt. The health record retains a monotonic management-sequence watermark: a delayed older success or failure cannot erase a newer result. A recreated tenant cannot execute or view its predecessor's request.

The admin panel displays the latest 20 request receipts and the customer audit. Customer DTOs continue to omit private management records. Pause/resume records the prior state and website flag; a phone-only testing workspace resumes to testing without enabling website chat.

Customer detail combines website conversations with up to 60 recent managed texting contacts within its 100-record conversation view. Authoritative managed SMS history replaces an older projection for the same contact. Customer and front-desk messages retain their processing state, so an accepted or uncertain send is not presented as delivered. Provider references, credentials and a predecessor workspace's messages are excluded from the managed history DTO.

Its seven HTTP calls are intercepted same-site worker fixtures, with no provider request.

It covers cost/authority forms, matched Google state versus forged success URLs, expired access, delayed sign-out responses, request timeout recovery, managed SMS record visibility/deduplication/redaction and the actual operator service-check dialog/audit/receipt. The first receipt retains the two real expired-session/sign-out failures found before their fixes.
