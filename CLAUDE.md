# Machines & Cloud — site repo guide

Marketing site for machinesandcloud.com: AI front desk agents (website chat + phone) for service businesses, Houston based, founder led.
Static HTML with shared `styles.css`/`script.js`, core-page `site-refresh.css`, the inline `stories.js` walkthrough, a lazy browser-voice bridge, and the separate `agent-widget.js` sales desk. Netlify Functions power those agents and the client product (onboarding, owner portal, chat, SMS, voice, scheduler, billing). See `OPERATIONS.md` for the flow, storage, env vars, and per-client steps.

It does not authorize a call, enforce the external test budget or restrict every outbound route: use it only for the specifically approved browser-voice rehearsal with a network allow-list and preserved request ledger. ## The live agent
- `agent-widget.js` renders the corner launcher ("Ask the front desk") + panel on every page except those with `data-no-widget` on body, keeps the transcript in sessionStorage, POSTs `{messages, page, stream: true}` to `/api/chat` (persona `mc`) and renders the NDJSON stream as it arrives (`{t:"delta",text}` lines, then `{t:"done",reply,events}` or `{t:"error",error}`), falls back to a plain JSON reply if the response is not a stream, shows four quick-question chips on a fresh chat, has a New chat button, a 45 s abort, and opens on any `[data-open-agent]` element, `a[href="#agent"]`, or the `#agent` hash. Test the agent with `scratchpad`-style scripts that POST with `stream: false` for a plain JSON reply.
- `netlify/functions/chat.mjs` exposes sales (`mc`/default), named fictional practice and real-client modes. Sales facts and strict tools live in `lib/sales-desk.mjs`: exact call-volume planning, required-workflow fit and allowlisted optional setup/example/scheduling actions. No sales tool captures leads, sends messages, creates an account or books a call. Sales uses the existing `claude-opus-5-5` at medium adaptive effort, 3,072 tokens per request, at most three iterations, SDK retries zero and final-only delivery after tools. Max-token/incomplete replies fail rather than masquerade as complete. Full alternating sales context accepts up to61 messages (user1,500chars, assistant16,000, aggregate120,000); other modes keep their existing limits/defaults. `lib/sales-budget.mjs` atomically reserves accepted logical turns:50 shared/day,20/IP/day by default in Houston; failures consume allowance. Operator env limits and0 kill switches are independent of tenant/demo budgets. These are bounded request starts, not a dollar cap. Widget history stores completed pairs in tab session storage, failed questions separately; it supports stop/retry/reset, correction continuity, copy/save, accessible modal focus and explicit demo navigation without starting the microphone. Tests use offline fixtures; real-model intelligence is not established by them. See `product/SALES-DESK.md` and `product/SALES-DESK-QA.md` for the acceptance rubric and immutable proof. The separately authorized real-AI review uses `scripts/sales-desk-eval.mjs`, a frozen plan and a fresh capped ledger; never reopen a closed phase. Publication requires its own exact approved batch; use the public-only build, never a root-directory draft deploy.
- Dependencies: `package.json` contains the Anthropic SDK and pinned browser-voice build dependencies. `netlify.toml` sets `publish = "."`, builds the local browser-voice bundle/license notices, then runs smoke and the configured-key scheduler gate in separate processes. Functions use esbuild bundling; `node_modules/` is gitignored.
